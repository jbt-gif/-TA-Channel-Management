<objective>
## Goal
Wire error tracking (Sentry) into the backend and frontend, and stand up uptime monitoring against the real staging URLs — so a crash, an unhandled route error, or a silently-failing PushQueue worker tick becomes a visible alert instead of something nobody notices until a hotel calls to complain.

## Purpose
ROADMAP.md's Phase 7 lists "error + uptime monitoring wired in" as a named scope item, and PROJECT.md's Success Metrics table has two rows still "Not started": *Silent failures (payment/webhook/sync): Zero — every failure visibly logged and alerted* and *Error + uptime monitoring live before first real hotel*. Right now, nothing tells anyone when something breaks — `src/lib/pushQueueWorker.ts`'s one catch block only does `console.error`, invisible unless someone is actively tailing Render's logs. This plan closes that gap.

This depends on 07-01 genuinely, not reflexively: the uptime monitors point at 07-01's real Render/Vercel URLs, which didn't exist before that plan.

**Side benefit, not the goal:** pinging Render's `/health` every 5 minutes (well under Render free tier's ~15-minute idle-sleep threshold) will likely also keep the container warm, incidentally mitigating the Deferred Issue logged at 07-01 plan-critic (2026-08-28) about the in-process PushQueue worker going silent when Render sleeps. Confirm this empirically during Task 4's verification — don't assume it as a design goal, since Render's exact sleep/wake behavior under external pings isn't something this project has tested yet.

## Output
- `@sentry/node` wired into the backend (route errors + the PushQueue worker's existing catch block), optional via `SENTRY_DSN` — missing/empty does not crash the server, unlike `CORS_ORIGIN`/`JWT_SECRET`'s fail-fast pattern, since this is observability, not a security boundary
- `@sentry/react` wired into the frontend, optional via `VITE_SENTRY_DSN`
- A free-tier Sentry project (or two: one Node, one React) with DSNs set only in Render's/Vercel's dashboards, never committed
- A free-tier UptimeRobot account with two monitors (Render `/health`, Vercel frontend root) and a working email alert contact
</objective>
