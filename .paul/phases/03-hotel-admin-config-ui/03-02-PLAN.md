<objective>
## Goal
Frontend admin UI for hotel self-configuration: a page where a HOTEL_ADMIN/SUPER_ADMIN can create/edit/delete room types and rate plans, and view/update the hotel's downpayment policy — consuming 03-01's backend API entirely from the browser.

## Purpose
03-01 built the CRUD API but it's only reachable via curl/scripts. ROADMAP.md's Phase 3 goal ("Hotel staff self-configure their own room types and rate plans — no founder involvement required per hotel") isn't real until a hotel admin can actually do this by clicking, matching this project's established discipline (every phase after Phase 1 delivers something clickable, not just an API).

## Output
- `frontend/src/api/admin.ts` — typed client for all 03-01 endpoints with discriminated errors (same pattern as `api/bookings.ts`)
- `frontend/src/pages/Admin.tsx` — room type + rate plan CRUD UI, policy settings section
- `/admin` route, reachable only to HOTEL_ADMIN/SUPER_ADMIN (nav link + route guard)
- Small backend addition: `GET /api/room-types` now includes each rate plan's `basePrice` (needed so the edit form can show the current price, not just accept a blind overwrite)
</objective>

    - `createRoomType(input: { name: string; baseCapacity: number })`
    - `updateRoomType(id: string, input: Partial<{ name: string; baseCapacity: number }>)`
    - `deleteRoomType(id: string)`
    - `createRatePlan(roomTypeId: string, input: { name: string; isRefundable: boolean; includesBreakfast: boolean; basePrice: number })`
    - `updateRatePlan(id: string, input: Partial<{ name: string; isRefundable: boolean; includesBreakfast: boolean; basePrice: number }>)`
    - `deleteRatePlan(id: string)`
    - `getPolicy(): Promise<{ downpaymentPercent: number }>`
    - `updatePolicy(downpaymentPercent: number): Promise<{ downpaymentPercent: number }>`
    Each mutating call: parse the response status the same way `createBooking` does (201/200 → success, 400/403/404/409 → the matching typed error with the backend's message, anything else → generic `ServerError`).

    <!-- audit-added: strongly-recommended finding 2 -->
    **Type every money-shaped field as `string`, not `number`, in all `admin.ts` response types** (`basePrice` on create/update-rate-plan responses, same as the `RatePlanSummary.basePrice` change above). Prisma's `Decimal` serializes to a JSON string, not a number — 03-01's own throwaway test script had to wrap every price comparison in `Number(...)` to work at all. Declaring these as `number` in the client's types would compile but silently produce wrong runtime behavior (string concatenation instead of arithmetic, or a value that only coincidentally displays correctly). `downpaymentPercent` is a real `Int` column and stays a `number` — this only applies to `basePrice`-shaped fields.
  </action>
  <verify>
    `curl http://localhost:3000/api/room-types` (as an authenticated user) shows `basePrice` on each rate plan. `npm run build` (frontend) type-checks cleanly against the new client.
